## Technical blockers for future adoption

### 1. Existing EHA Mermaid output contract changes by default

Before this PR, `eha_state_mermaid` returned Mermaid source for an ordinary call. The PR changes the default response to a JSON envelope and adds `responseFormat: mermaid_source` as an explicit legacy mode.

That is not backward compatible for existing callers: an old caller does not know it must begin sending a newly introduced argument. A later hardening PR must either preserve the old default and make JSON opt-in, or introduce an explicitly versioned/new tool contract.

### 2. Product-visible Graphify selection exceeds supported runtime evidence

The TUI/settings expose `graphify` as a normal selectable context-graph provider. However, the only exact transitive provider lock is explicitly documented as Windows + Python 3.14.

Hosted acceptance runs Python 3.10/3.12 on Ubuntu and Windows. The actual provider execution test skips when `.runtime/graphify-provider` is absent; hosted CI therefore validates provider-absent behavior rather than an enabled Graphify runtime on the supported matrix.

A future adoption must either keep Graphify behind an explicit incubation/developer boundary or establish supported exact runtime/install profiles and execution evidence before normal UI exposure.

### 3. Ambient Python interpreter identity

`repo_context_provider.ts` launches the adapter through bare `python` from PATH. This can differ from the interpreter/runtime used to install or launch CodeSleuth and is not a stable cross-platform runtime identity. A future provider contract should resolve an explicit interpreter/runtime instead of relying on ambient PATH.
