## Blocking findings

### HIGH — source label weakens exact CodeSleuth identity

`source_label()` renders the source as a compact remote plus optional `@ref`, but ignores the recorded `source.commit`.

Consequences:

- detached/self-install metadata with a null ref can collapse to the remote name only;
- branch-backed installs display a movable branch ref instead of the exact recorded commit;
- two distinct installed CodeSleuth revisions from the same remote/ref can become indistinguishable in the TUI catalog.

This conflicts with the lifecycle contract that exact commit identity is authoritative and detached checkouts are normal. The catalog must display the recorded exact commit identity, normally as a short SHA, with ref only as supplemental context. Add regression coverage for detached/null-ref source metadata and for a ref plus exact commit.

### HIGH — refresh pruning can silently forget existing repositories

`list_tracked_repositories(refresh=True)` defaults `prune_missing=True`, but pruning is keyed to `not live.get("reachable")` rather than actual path absence.

`_probe_entry()` also sets `reachable=False` whenever lifecycle/dependency probing raises. Therefore an existing checkout that is malformed, conflicted, temporarily unreadable, or otherwise unprobeable can be silently removed from the persistent host catalog during refresh.

The documented behavior is narrower: remove paths that no longer exist. Existing-but-unprobeable paths must remain recorded with an explicit degraded/error/unreachable state. Add a regression test proving that an existing directory with a failing lifecycle probe is preserved.
